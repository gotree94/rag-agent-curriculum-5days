## 3. 교수안 상세

### 3-1. 기업 환경의 RAG (50분)
- **왜 기업은 RAG인가**: 사내 문서는 외부에 없고, 최신이며, 접근권한이 있다
- 프라이빗 데이터 유형: 규정/정책, 기술문서, 회의록, 고객지원 이력, DB
- 요구사항: 정확성, 출처 추적, 권한 통제, 비용, 응답속도
- 2일차 v1의 한계 예고: (1) 키워드 일치 기반 질문에 약함 (2) 노이즈 (3) 환각 (4) 측정 불가

### 3-2. Hallucination과 가드레일 (50분)
- 정의: 근거 없이 사실처럼 답하는 현상
- 원인: 학습 지식으로 과잉 일반화, 검색 실패, 프롬프트의 애매함
- 방지 전략:
  1. **근거 인용 강제** — 출처 파일명/문장 인용
  2. **답변 거절** — 문서에 없으면 "찾을 수 없음"
  3. **검색 신뢰도 임계값** — 유사도 낮으면 답하지 않음
  4. **온도 낮추기** — 추출형 질문은 temperature 0
- 🧪 실습 포인트: 문서에 없는 질문(예: CEO 이름)으로 baseline vs guard를 비교

### 3-3. 검색 품질 향상 (40분 + 실습)
| 기법 | 원리 | 언제 |
|---|---|---|
| 하이브리드 검색 | 벡터(의미)+BM25(키워드) 결합(RRF) | 고유명사/숫자/코드 포함 질문 |
| 리랭커 | 상위 N개를 cross-encoder로 재정렬 | 정밀도가 중요할 때 |
| Multi-query | 질의를 여러 개로 확장 후 합집합 | 표현이 다양한 질문 |
| 메타데이터 필터 | 부서/문서종류/권한으로 범위 제한 | 접근권한·정확도 동시 향상 |

### 3-4. RAG 평가 (RAGAS) (40분)
- 왜 평가가 필요한가: "느낌"이 아니라 "수치"로 개선
- RAGAS 4대 지표:
  - **Faithfulness**: 답변이 문맥에 근거했는가
  - **Answer Relevancy**: 답변이 질문에 부합하는가
  - **Context Precision**: 검색 문맥 중 정답 근거 비율(정밀도)
  - **Context Recall**: 정답 근거를 얼마나 검색했는가(재현율)
- 평가셋: 질문 + 정답(ground_truth) + 검색문맥 + 생성답변
- 해석: Precision 낮으면 → 검색 개선 / Faithfulness 낮으면 → 프롬프트·가드레일 개선

### 3-5. 보안과 아키텍처 (20분)
- 접근 권한 반영(문서 ACL → 메타데이터 필터)
- 개인정보(PII) 마스킹(주민번호/전화/이메일)
- 데이터 경계: SaaS API vs 프라이빗 클라우드 vs 온프레미스(로컬 LLM)
- 참조 아키텍처:
  `수집 → 정제/마스킹 → 청킹 → 임베딩 → 벡터DB(권한) → (하이브리드+리랭크) → 가드레일 → 생성 → 로깅/평가`
