# 최종 프로젝트 가이드 — "사내 업무 지원 AI 어시스턴트"

> 5일차 오후 (약 2.5시간 개발 + 0.7시간 발표)
> 팀 2~4인 · 산출물: 동작하는 데모 + 아키텍처 설명 + 발표

## 1. 목표

5일간 배운 **LLM · RAG · 에이전트 · LangGraph · MCP**를 하나로 통합해,
사내 업무를 실제로 돕는 AI 어시스턴트를 팀별로 완성한다.

## 2. 주제 예시 (택 1 또는 자유)

| 주제 | 핵심 기능 |
|---|---|
| 사내 규정/매뉴얼 QA 봇 | 규정 문서 RAG + 출처 인용 |
| 기술문서(데이터시트) 검색 에이전트 | PDF/DOCX RAG + 하이브리드 검색 |
| 고객 문의 응대 어시스턴트 | FAQ RAG + 계산/조회 도구 |
| 설비 장애 조치 가이드 에이전트 | 매뉴얼 RAG + 단계별 가이드 생성 |
| 인사·복지 안내 챗봇 | 문서 검색 + 직원 조회 + 규정 요약 |

> 과정 공용 샘플 문서(`00-environment/sample-data/`)를 그대로 사용해도 되고,
> 팀에서 문서를 추가해도 된다.

## 3. 필수 요구사항 (체크리스트)

- [ ] **R1. RAG** — 문서를 인덱싱하고, 질문에 근거 기반으로 답변한다
- [ ] **R2. 출처 표시** — 답변에 참조한 문서(파일명/조항)를 표시한다
- [ ] **R3. 도구/에이전트** — 최소 1개 도구 호출 또는 LangGraph 워크플로우를 포함한다
- [ ] **R4. 환각 방지** — 문서에 없으면 "찾을 수 없음"을 반환한다(가드레일)
- [ ] **R5. 인터페이스** — Streamlit UI 또는 CLI로 실행 가능하다
- [ ] **R6. 아키텍처 설명** — 데이터 흐름을 도식/문서로 설명한다

### 가산점 (선택)
- 하이브리드 검색(3일차) / 리랭커 적용
- MCP 서버(5일차) 연동
- 멀티 에이전트(Supervisor) 구성
- RAGAS 등 정량 평가 결과 포함

## 4. 권장 아키텍처 (예시)

```
[문서] 00-environment/sample-data/*.md, *.pdf
   │  (로드 → 청킹 → 임베딩)
   ▼
[벡터 DB: Chroma/FAISS]  +  [BM25 키워드 인덱스]
   │  (하이브리드 검색 + 리랭커)
   ▼
[LangGraph 워크플로우]
   ├─ supervisor (요청 분류)
   ├─ rag_worker  (문서 QA)
   ├─ tool_worker (계산/조회)
   └─ policy_worker (규정 검색)
   │  (가드레일: 근거 없으면 거절)
   ▼
[Streamlit UI] — 답변 + 출처 + 검색된 원문
```

## 5. 진행 순서 (2.5시간 예시)

| 시간 | 할 일 |
|---|---|
| 0:00~0:15 | 주제 확정, 역할 분담(데이터/에이전트/UI/발표) |
| 0:15~0:45 | 문서 준비 + 인덱싱(RAG 파이프라인) |
| 0:45~1:30 | 에이전트/워크플로우 구성 (도구·조건부 분기) |
| 1:30~2:00 | UI 연결 + 가드레일 적용 |
| 2:00~2:20 | 테스트(정상/환각/도구 케이스) + 데모 시나리오 |
| 2:20~2:30 | 발표 자료 정리 |

## 6. 발표 가이드 (팀당 5~7분)

1. **문제 정의** (30초) — 어떤 업무를 돕는가
2. **데모** (2~3분) — 정상 질문 2개 + 도구 사용 1개 + 환각 방지 1개
3. **아키텍처** (1분) — 데이터 흐름, 사용 기술
4. **도전/해결** (1분) — 막힌 점과 해결
5. **회고/개선** (30초) — 다음에 개선할 점

## 7. 평가 루브릭 (100점)

| 항목 | 배점 | 기준 |
|---|---|---|
| 동작 완성도 | 30 | 요구사항 R1~R5 충족, 데모가 안정적으로 동작 |
| RAG 품질 | 20 | 근거 기반 답변, 출처 정확, 환각 저감 |
| 에이전트 활용 | 20 | 도구/그래프를 적절히 활용, 라우팅 합리적 |
| 아키텍처 설계 | 15 | 구조가 명확하고 확장 가능 |
| 발표/협업 | 15 | 전달력, 역할 분담, 피드백 반영 |

## 8. 제출물

- 소스 코드 (팀 폴더 또는 저장소)
- `README.md`: 실행 방법, 아키텍처 도식, 사용 문서 출처
- (선택) 평가 결과 CSV (RAGAS 또는 자체 평가)

## 9. 자주 하는 실수

- 문서를 인덱싱했는데 **오래된 벡터 DB를 재사용** (문서 변경 후 재인덱싱 필요)
- 출처가 없거나 틀린 답변 → 프롬프트에 "문서 밖 지식 금지" 명시
- 도구가 너무 많아 선택 혼선 → 역할별로 에이전트 분리(Supervisor)
- API 키 노출 → `.env` 사용, 캡처/발표화면 마스킹
